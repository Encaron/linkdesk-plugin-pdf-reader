## 一、用户原话与诉求（2026-10-08）

> 「1. 那个『打开方式…』和『在市场搜索阅读器』这两个按钮（错误态两式 两个页面都是这样）我的建议是**圆角继续跟主题**，其他的，比如**强调色，字体颜色**等就**不要跟主题**了。因为 pdf 阅读器插件**背景只有黑/白**，让这两个按钮跟主题，很多时候会导致**看不清按钮和按钮内的字**。你听懂我的诉求了吗？」

> 「做完直接发版一个 pdf 阅读器插件吧 然后归档『PDF阅读器插件』任务」

**做**：错误态两式（「此 PDF 无法打开」/「此 PDF 已加密」）里的两颗动作钮——「打开方式…」与「在市场搜索阅读器」——**颜色一律改走插件自有色族**；**圆角仍随壳主题**（`--radius-sm`）。
**不做**：⛔ 不碰壳/`@linkdesk/ui` 的共享 `Button` 本体（改它波及所有插件）；⛔ 不新增色值或 token；⛔ 不动命令族与声明面。

## 二、病灶（实测定因，⛔ 不是推测）

那两颗钮此前直接吃壳共享件 `Button` 的 **ghost 变体**，而 ghost 变体的颜色全部取自**壳主题变量**（`--separator` 描边 / `--text-secondary` 字 / `--hover-overlay` 悬停底 / `--text-primary` / `--radius-sm` 圆角）；**底是透明**的，于是钮的「形状」实际由**底下那张面板**决定——而本插件的底色只有纸白 `#f1f2f0`（`--pdf-bg-surface`）与夜间 `#0f172a` 两档，**与壳主题无关**。

⇒ 壳主题一换，钮的取色还在跟壳走，底却由插件档位决定，两者撞在任何一侧都出事。**实测环境 = 用户当前主题**（`data-theme="dark"`：`--text-primary #4EC9B0` · `--text-secondary #35A584` · `--accent #00E676` · `--separator #162A24` · `--radius-sm 4px`）：

| 档 | 旧读数（0.1.0，实测 computed） | 病灶 |
|:--|:--|:--|
| 纸白 | 字 `rgb(53,165,132)` = `--text-secondary` ／ 底**透明**（透出 `#f1f2f0`）／ 描边 `rgb(22,42,36)` = `--separator` | **字对底 2.72:1**——深青字坐在近白面板上，**连 3:1 都不到**，这就是「字看不清」 |
| 夜间 | 同上（字/底/描边一个数） ／ 底透出 `#0f172a` | 字 5.84:1 尚可，但**描边对底只剩 1.18:1**（≈没描边）＋ 底透明 ⇒ **钮没有形**，这就是「按钮看不清」 |

🔴 **一句话**：用户看到的是两件不同的事故——**纸白档字先糊**（2.72:1），**夜间档钮先没**（描边 1.18:1、无钮底）。

🔴 **而设计图本来就写的是固定色**：[06-设计图.html §`.state .btn`](../06-设计图.html) = `background:#fff;border:1px solid var(--pg-line);border-radius:6px`——**白底＋插件自己的线色**，⛔ 从没有「跟主题取色」这一条。当初接共享件时把颜色一并接了过来，是**接歪**，本格是**回正**，不是新决定。

## 三、改法（只把圆角留给壳）

落点**一处**：`src/styles/reader.css`，紧接 `.pdf-reader-error-actions` 之后加一段（+24 行，含注释）：

```css
.pdf-reader-error-actions .ldk-button {
  background: var(--pdf-bg-page);
  border-color: var(--pdf-border-page);
  color: var(--pdf-ink-ui);
}
.pdf-reader-error-actions .ldk-button:hover:not(:disabled) {
  background: var(--pdf-bg-page);
  border-color: var(--pdf-accent);
  color: var(--pdf-ink-ui);
  opacity: 1;
}
.pdf-reader-error-actions .ldk-button:focus-visible {
  outline: 2px solid var(--pdf-accent);
  outline-offset: 1px;
}
```

三条口径（都写在代码注释里，防下次「顺手归一」）：

1. **颜色全走插件自有色族**：底 `--pdf-bg-page` · 描边 `--pdf-border-page` · 字 `--pdf-ink-ui` · 悬停描边 `--pdf-accent`。⛔ 一处新色值都没加——`--pdf-border-page` **本就是**本仓的控件线色（缩略图 `.pdf-reader-thumb`、搜索条、目录行都用它）⇒ 这颗钮从此与仓内别的控件同族。
2. 🔴 **只把圆角留给壳**：代码里**刻意不写 `border-radius`**——`--radius-sm` 由共享件 `.ldk-button` 自带，用户要的「圆角继续跟主题」原样成立。**内边距与字号也照旧随共享件**（尺寸口径不在本处分叉）。
3. **覆盖写在插件自己的作用域里**（`.pdf-reader-error-actions` 前缀），与既有先例同款（`marketplace` 的 `.marketplace-ms-check-slot .ldk-button`、`serial-monitor` 的 `.serial-monitor-control-bar .ldk-selectbox-trigger`）——⛔ 不动共享件本体。

### 四.4 T8 留的第二件：**「双击即起阅读器面」复验**（✅ 本格结清）

T8 原文：本机那个开着的 `.pdf` 标签是**编辑器插件的二进制提示页**，双击文件树该行只聚焦已有标签、没另起阅读器面 ⇒ 当时**没当成已复验**。本格按**双击的真实两腿**重放（源 = file-tree `src/views/FoldersView.tsx` 的 `doOpenFile`）：

```
双击 → handleOpenFile → doOpenFile(filePath, name, "pin")
     → ext = extension(name)
     → pluginId = await lk.fileAssociation.getPluginFor(ext)      ← 关联腿
     → lk.tabs.create(pluginId, {filePath, sourceId, label, pinned:true})  ← 起面腿
```

| 腿 | 读数 |
|:--|:--|
| 关联 | `fileAssociation.getPluginFor("pdf")` = **`"pdf-reader"`**；`listHandlersFor(".pdf")` = `pdf-reader`（`isCurrent:true`）＋ `editor`（退次选） |
| 起面 | `tabs.create("pdf-reader", {filePath, sourceId, label:"broken.pdf", pinned:true})` → 标签表出现 **`pdf-reader-C__…_broken_pdf`**（`title:"broken.pdf"` · `pluginId:"pdf-reader"` · `pinned:true`），错误面「此 PDF 无法打开」起；`encrypted.pdf` 同款起来（「此 PDF 已加密」） |

⚠️ **诚实限定**：重放的是**壳的开路由两腿**（同一对 API 调用），**React 的 `onDoubleClick` 监听器本身没被驱动**（要驱动得先把临时目录加进工作区＝改用户机器状态，⛔ 本格不做）。
➖ 附一条**顺带**读数（不是判据）：会话期间机上有另一只标签开着**真 PDF**（`Downloads/单片糜渠东新STM32…pdf`），在**已发布 0.1.1** 上正常渲染——阅读面在场（4 张 canvas ＋ 工具条）、无错误面 ⇒ 「发行版不只能开错误态」这一条有实机旁证。

### 四.5 两式的 DOM 作用域（工具面坑，本格又中一次）

池页里**每开一份文档就多挂一个 `.pdf-reader-root`**（本格实测 `roots: 2`）。按 `document.querySelector(".pdf-reader-error-title")` 读，拿到的是 **DOM 里第一个**面板——第一轮测「加密」时读回来的其实是**隔壁 broken 面板**的标题与描述（看着像插件错了，实际是读数错）。⇒ 读数一律**按面板身份定位**（本格用「标题含目标串」`find`），⛔ 不用文档序。同族坑 T7 已记过（「所有面都挂着、只有活动那张可见」），本格是它的**变体**（两个面都在，取错了那个）。

### 四.6 圆角「跟主题」这一腿的证据

实测值始终 = **4px**，与当时主题的 `--radius-sm` 同值；**同一会话早前另一套主题下读到的 `--radius-sm` = 20px，钮的圆角同步变 20px** ⇒ 「圆角跟主题」不是纸面声明，是会动的。内边距 `4px 12px`、字号 `13px` 全程来自共享件（本格未覆写）。

## 六、教训

1. 🔴 **「插件自有底色面」里的控件，⛔ 不许吃壳主题取色**（本档判据成文）：本插件的纸白/夜间两档**与壳主题无关**，而共享件 `Button` 的 ghost 变体**整身都是壳主题变量**（字/描边/悬停底/焦点色）⇒ 两者各自「正确」也必然撞。**圆角跟主题无妨**（尺寸类不涉对比），**颜色类一律走插件色族**。可复用判据：*这个控件坐在谁定的底上？底归插件 ⇒ 颜色归插件。*
2. 🔴 **「同版本副本永不刷新」的反面**：本格吃的这一口是**身份判据过期**——T8 用 `index.bundle.js` 的 md5 认「上机那份＝发布那份」，而 0.1.1 只改了 CSS ⇒ **两个版本的 JS 逐字节相同**，那套判据对此版**毫无分辨力**。⇒ 记身份要用**本次真改过的那个产物**（或直接用 zip md5），⛔ 别把它当恒定指纹。
3. 🔴 **改完包，池页要真重载**（沿用 T4 教训）：`needRestart:true` 是恒真回执（bundle 同 URL 已进模块缓存），⛔ 别以为更新完当场就换新码；本格所有读数都在「清自定义协议缓存 ＋ 等 `performance.timeOrigin` 真变」之后取。
4. 🔴 **读数按「面板身份」定位，不按文档序**（§四.5）：多文档并存时 `querySelector` 会读到隔壁面板，**症状是「插件好像错了」，实际是读数错了**。
5. ⚠️ **安装包按扩展名分派**：把发布资产改名叫 `.zip` 再 `install()` ⇒ 回「**不是有效插件（缺少 plugin.json）**」（资产真名 `pdf-reader.linkdesk-plugin`，本质是 zip 容器，壳按扩展名走）；改回扩展名即装成功。
6. ⚠️ **`checkUpdates` 要吃 catalogUrl**（`checkUpdates(pluginId, catalogUrl)`），空调用会报 `plugins:resolvePath … Received undefined`；catalogUrl 由市场层提供（官方源常量住 marketplace 仓 `marketSourceAdd` 一线）。
7. ⚠️ **`tabs.openOrFocus(id,{sourceId})` 不会切来源**：目标插件已有活动视图时它只**聚焦**，`sourceId` 被忽略（本轮第一版读数就因此拿到旧文档）；要开指定文档得先关掉或用 **`tabs.create`**（双击路由用的正是 `create`）。
8. ⚠️ **底色是每文档的持久态**：`setBackground` 回 `{ok:true, noop:true, reason:"already-night"}` 是**合法回执不是失败**；A/B 必须**显式 force** 目标档再读，⛔ 别靠默认档（本格第一版就把 night 当 paper 记过）。
9. ⚠️ **插件样式表跨源 ⇒ CSSOM 读不到**：`linkdesk://…/index.bundle.css` 是异源 `<link>`，`stylesheets[i].cssRules` 抛 `SecurityError`；要看样式就读**交付字节**（页内 `fetch(url,{cache:'no-store'})`，顺带证明「页上跑的是哪一份」）。
10. ⚠️ **`update(id, {url, allowOlder:true})` 能装本地已发布包** ⇒ 「降级做 A/B」与「同机双版本对比」这两件事**不必手工复制目录**，走正门即可（本格 A/B 就是这么来的）。

## 七、边界（本格没做什么）

- ⛔ **不动共享件**：`.ldk-button` 本体（壳 / `@linkdesk/ui`）一行未改——改它会波及所有插件；本格只在本插件作用域内覆盖（判据 A：插件自绘面的取色归插件，消费宿主声明的**控件**才住壳）。
- ⛔ **零新增色值 / token**：只用 `tokens.css` 里既有的 `--pdf-bg-page` / `--pdf-border-page` / `--pdf-ink-ui` / `--pdf-accent`（T7 自查口径「`tokens.css` 之外零 hex」继续成立）。
- ⛔ **声明面 / 命令族一字未动**：仍 **12 条命令**、`fileAssociations` / 配置项 / i18n 声明零变更；本格**零新增可见串** ⇒ 翻译腿无需动作（⑧ 段 48 key / 19 条声明串全绿即为复核读数）。
- ⛔ **不动出厂种子**、⛔ **不动壳源码**（`src/` / `electron/` 零 diff）。
- ⛔ **未在 UI 逐条点选**：hover 态只到规则级证据（§四.2 诚实边界）；「双击」只重放壳的开路由两腿、未驱动 React 监听器（§四.4）。
- ⚠️ **留给用户的复查点**：纸白档钮的**轮廓**现在是一条发丝线（钮底对面板 1.12:1，设计图原口径）——若实机觉得太淡，改 `--pdf-border-page` 那一档 token 即可（一处改、全仓控件同步）。
